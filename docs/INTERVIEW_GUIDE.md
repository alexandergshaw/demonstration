# Throughline walkthrough

## Suggested ten minutes (not prescribed by the assignment)

1. **Product thesis and first use, 1 minute:** Show the inline purpose overview, or replay it through **Guide → Start here**. Explain the job: turn student work into one teaching move and a usable team meeting. Briefly open **Preview what you’ll make** to show the source packet, six-activity agenda and separate checks. This is a structural preview; it does not write decisions into the cycle. Point out **Prepare here → Meet and teach with the team → Return to Reflect** before entering the evidence.
2. **Pilot target, 1 minute:** A single-grade math PLC leader preparing a 50-minute meeting, with an unvalidated preparation target of 20 minutes. All lesson materials and results are fictional.
3. **Evidence, 2 minutes:** Show the comparison of 89 correct fractions with 46 adequate explanations beside student work. Select a response. Use **By class** or **Task & sources** to inspect a specific question, then open the older observation and explain its one-classroom scope.
4. **Interpret, 2 minutes:** Write in **Notice** while the original source stays beside the editor. Open **Test an alternative** and show the three routes: **Revise interpretation**, **Inspect source**, or **Keep interpretation & explain uncertainty**. Keeping records consideration and opens **Choose a focus** after the save succeeds. Explain the source, the alternative and what would change your mind in the focus; the app does not write the conclusion. On a smaller screen, **View selected evidence & task** opens a source dialog.
5. **Plan, meeting handoff and later reflection, 2 minutes:** Show the teaching move, select one activity and optionally open its facilitator self-check. Set separate implementation and learning checks, then **Review meeting plan** before approval. Pause on **Your meeting is ready**: the next real-world action is to open/export the kit, run the meeting and try the teaching move. For this fictional walkthrough, explicitly move forward in time before choosing **Go to reflection**. Point out that the active cycle has no collected follow-up dataset; record what was tried and the evidence needed next.
6. **Design judgment, 2 minutes:** Open a separate worked example if useful, then **Guide → About this demo → How we would test this**. Explain the proposed workflow comparison, instructional review, total burden and adopt/revise/stop criteria. The downloadable research handout contains no collected findings.

## Example inputs

Type or adapt these as fictional demonstration notes; the app does not supply them as the leader's decisions.

- Interpretation: “Many students selected an equivalent fraction correctly, but fewer could explain why. The wording may also influence that difference.”
- Focus: “Response B describes a procedure without explaining equal amounts. Even if task wording contributed, I would explore questions about the same whole; two examples do not establish a class-wide pattern.”
- Teaching action: “In the next lesson, teachers will ask students to explain how partitioning the same half into two equal parts changes the number of parts but preserves the amount, using a drawing or words.”
- Implementation check: “Each teacher brings a lesson note recording the question asked, whether students explained their own reasoning and any adjustment to the routine.”
- Learning check: “Collect independent fraction-equivalence explanations on a comparable task and use the same rubric to look for equal amounts of the same whole.”
- Reflection: “No collected follow-up work is attached to this cycle yet. We need a dated task, shared rubric, response coverage and an implementation record before deciding whether to keep or revise the move.”

## Navigation and optional demonstrations

**Cycle actions → New cycle** starts a fresh planning cycle. The inline introduction appears only on Evidence when it has not been dismissed and there is no authored decision, modified agenda/owner, follow-up report or pending review. It is not an automatic modal, and the evidence below it can be used immediately. **Start with the evidence** records dismissal in the separate browser-local learning preference and returns focus to the main heading; it does not approve or author anything. A new cycle does not reset that preference. Use **Guide → Start here** to replay the overview for a demonstration or returning user instead of clearing their data.

As the leader progresses, point to the phase, purpose and **You’ll take forward** line in the header. These connect each task to a concrete output rather than merely identifying a screen: selected evidence, a defensible focus, reviewed meeting materials and a supported next action. **Help with this step → Walkthrough** explains why the stage exists. The meeting-ready phase makes the real-world meeting and lesson explicit before reflection.

Use the top-bar **Decisions** control to inspect the current cycle's writing and approval states without adding a permanent history column to the workspace. Guide, the structural preview and contextual help remain optional. No welcome screen or lesson must be completed to work on the cycle.

At one stage, open **Help me think this through** to show the short question, task-specific guidance and **Self-check**. Close it to return to the main work. Explain that the self-check is a prompt for the leader, not a rating or automatic completion rule. Use the active activity's help in Plan rather than opening a second instruction panel for every agenda row.

Show an unset collector or date honestly. Those arrangements are optional for approval, but remain visible on the ready screen so the team can agree them. **Edit collection details** opens the learning-check editor and focuses the collector. From Reflect, the same route is **Review what to collect → Update collection plan**. A changed commitment requires reapproval; authored action, agenda and reflection text remain available.

To demonstrate freshness, use **Guide → About this demo → Presenter tools → Simulate new results**. Compare the October 29 snapshot with the current sources, then keep the existing snapshot or create a revised draft. Explain that the original cycle survives, source selection and approvals reset for the revision, and retained writing needs reconsideration. Four responses are missing from the newer collection, and the repeated task may affect results. This is a simulated update.

**Reflect → Explore a worked example** or **Guide → Explore worked examples** opens a separate dialog. **Documented follow-up** illustrates how evidence could support a qualified decision. **Missing evidence** shows the fixed 46/120 → 56/120 case with an unknown follow-up task, date, scoring, cohort, coverage and implementation record. Neither example is an outcome for the active cycle. Return to the actual reflection to show the explicit unavailable-evidence state.

## Meeting materials

Edit Activity 2 with evidence-discussion instructions and Activity 4 with teaching-design or rehearsal instructions. Those exact directions carry into the participant handout. Use **Review meeting plan** to inspect the teaching move, all six activities, checks, sources and optional commitments before checking ownership and approving. The preview's Edit controls return to the relevant authoring area.

After approval saves, the app remains in Plan at **Your meeting is ready**. **Open meeting kit** provides six presentation sections, the source packet and the participant handout. Reloading restores this approved handoff rather than treating approval as classroom implementation. Export again after edits and reapproval; downloads are snapshots. A title-only older plan can still be opened, but should be expanded with useful facilitation directions before use.

Use the meeting kit first. **Go to reflection** is a separate action for after the lesson, not an automatic consequence of approval. If demonstrating a save failure, explain that failed confirmation leaves the draft and review available; it cannot award an approval or recorded-reflection success state. Saving a draft through Retry save is not a substitute for confirming again.

After **Record next step**, **Meeting kit → Download text plan** includes the current recorded reflection and implementation report. It states that implementation is self-reported, collection commitments are plans and no collected follow-up dataset is attached. The separate worked examples are not the cycle's results. Draft or invalidated reflections are excluded. The HTML meeting kit remains the approved initial meeting materials.

## Fallback

Run `npm run dev`, or `npm run build` and `npm run preview` for a production preview. The original `public-prototype.html` is an archival reference if a local Node server is unavailable; it does not include the current workspaces, local backend or meeting kit. Both implementations use scripted prompts.

Keep existing cycles when rehearsing. **Cycle actions → Reset cycle** clears only the selected cycle after confirmation. **Guide → About this demo → Presenter tools → Reset all saved cycles** is a separate confirmed action.

## Explain the scope honestly

The assignment accepts sketches, annotated screens, code or a clickable prototype; a native Figma file is not required. It suggests at most two hours of preparation and prioritizes reasoning over visual polish. Do not imply that subsequent implementation, review and deployment work fit that preparation budget.

The prototype uses browser-local data and no live AI. The 20-minute preparation target, clearer information hierarchy and expected benefits are hypotheses. Explain how a pilot would test preparation time, whether leaders can explain their choices, actual classroom implementation and comparable follow-up work before claiming impact. The [first-use research synthesis](onboarding/research.md#subsequent-synthesis-introducing-purpose-through-use) separates public-source evidence from product inference. A proposed first-use check asks whether leaders can explain the purpose, their decision authority, the expected output and when to return after teaching; no such study has been completed.

Browser testing was unavailable because browser use is disabled in the app settings. Code review and automated checks do not establish that rendered layouts, keyboard interactions or assistive-technology experiences have passed hands-on testing. [Guidance verification](GUIDANCE_VERIFICATION.md) records the workflow boundaries and a proposed leader-testing protocol; it contains no educator-study findings.
