# Manual agnostic loop in this project

`npm run loop -- status --state .agnostic-loop/throughline/state --output summary` reads the current run. `npm run loop:test` runs the restored core tests. `node tools/loop.mjs host status` shows the Throughline host record.

The manual engine is restored from the supplied `deadline/restored/src` snapshot. It preserves immutable artifact blobs, event revisions/idempotency, role and context independence, the two-round substantive review cap, exact write grants, executable gate evidence, stale-candidate checks and uncertain-operation retention. The small launcher supplies the bundled extension resolver. Automatic provider dispatch, its app-specific backlog adapter and copied qualification receipts are deliberately not enabled.

The host receives explicit JSON request files: `node tools/loop.mjs host start REQUEST.json`, `author`, `import`, `finish`, `review`, `advance`, `gates`, `verify-report` and `final-report`. A start request records assignment/activity/role, actual worker instance/context, exact paths, accepted input hashes, resources and declared deliverables; its packet is saved in `.agnostic-loop/throughline/packets`. An author request additionally names a source document and artifact slot; actual source bytes are imported into immutable storage. Review requests bind an actual independently authored report path/hash plus the exact artifact/hash, verdict and findings. Host identity is operator-attested, not cryptographically authenticated.

Registered gates invoke the local Node executable with `tools/repository-gate.mjs` and one fixed gate name: `app-tests`, `loop-tests` or `build`. Their output bytes, executable, arguments, candidate identity and process lifecycle are recorded. App tests use the root Vitest configuration. Loop tests use `tools/vitest.loop.config.mjs`. Build runs TypeScript then Vite. No shell-interpreted command is accepted by the wrapper.

Runtime records and planning/review documents are excluded from the source candidate to permit recording evidence without invalidating itself. Dependencies, Git metadata and build output are also excluded; package files and application/tool source remain included. Whole-candidate comparisons require serialized write windows even for independently authored code. A candidate change stales earlier gate evidence.

Bootstrap disclosure: initial archive extraction and the initial host/tool restoration occurred before engine admission. Root also prepared the initial package setup, model and App source during bootstrap. These are not retroactively claimed as supervised execution. The fresh run records accepted planning, subsequent bounded changes and verification against actual candidate bytes. No prior Resume-Tailor runtime receipts or qualification carry over.

Deployment is explicitly owned by the user. Local acceptance can establish only this local application and test run. Historical fixture success, source equality or a green build does not prove deployed behavior. The default gate runner retains uncertainty on timeout/output/launch failure; do not clear a lock merely because a process or chat disappeared. Use the core recovery commands only after observing termination and reconciling side effects.
