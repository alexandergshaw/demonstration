# Throughline design

## Structure and state

Keep React with TypeScript and Vite. Use a typed state model with pure validation and transition helpers, reusable presentational components, and a versioned browser-storage adapter. Evidence remains visible beside educator inputs in the Decision Thread. Preserve drafts when prerequisites are revoked; only completion/approval flags are invalidated. Keep current-source exports derived from validated state.

## Constraints

This is a fictional interview prototype with deterministic coaching. No backend or credentials are required. Browser storage is device-local and best-effort; failures must be visible without crashing or falsely claiming that work was saved. Do not infer teaching causality from old observations or the fictional follow-up score change. Source dates and observation scope stay visible.

## Experience

Retain the navy/teal, light-surface reference design and progressive four-stage navigation. Display clear reasons for gated actions and review-required states. Use semantic controls, labeled inputs, visible focus and error targeting. The layout changes to a stacked view on mobile. The follow-up separates implementation fidelity from learning evidence. Exports contain educator-approved content, not an automatically inferred diagnosis.

## Specialist disposition

Accessibility, state integrity and persistence require focused checks. Production authentication, district integrations, model safety and deployment specialists are omitted because those capabilities are outside the authorized prototype. This omission does not qualify the app for real student data.
