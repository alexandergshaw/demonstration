# Local backend acceptance criteria

- **C1 Repository and data:** A typed synchronous repository stores a validated, versioned database in localStorage. It provides immutable seeded workspace/evidence references and saved PLC cycles with IDs, titles, timestamps, revisions and model state. Reads return independent copies. Selected cycle persists. No network/server/external dependency is introduced.
- **C2 Cycle lifecycle:** Users create, select, rename, duplicate as draft and confirm deletion of cycles. Duplicate copies appropriate authored draft content but clears approval, consent, implementation/follow-up status and reflection. Deleting the final cycle is prevented. Reset affects only the current cycle. All successful lifecycle changes survive reload.
- **C3 Migration:** If the database is absent, a valid legacy `throughline.draft.v1` draft migrates once, retaining valid authored state and approvals. An existing database takes precedence. Legacy bytes remain until the new database write succeeds and may remain as a backup. Invalid legacy data cannot manufacture approvals or silently destroy usable storage.
- **C4 Model regression:** Existing educator approval gates, upstream invalidation, draft preservation, consent, saved reflection and current-approved export behavior remain correct across saves, cycle switches and reloads. The original 69 model tests remain passing.
- **C5 Failure and conflicts:** Schema/version/type/bounds/corruption checks prevent accepting invalid databases. Failed, quota or denied writes cannot report success or replace prior durable bytes; unsaved UI input remains visible with error and retry/recovery. Corrupt data is not silently overwritten. Stale expected revisions reject mutation. External storage changes are surfaced without silently overwriting current unsaved input. Revision checks are honestly described as optimistic, not cross-tab atomic transactions.
- **C6 React workflow:** React loads/saves cycles and reads displayed reference data through the repository. Accessible cycle controls and confirmation/recovery dialogs support create, switch, rename, duplicate, delete and reload without horizontal overflow. Existing four-stage educator workflow remains usable. User-facing controls describe PLC cycles, not internal database implementation.
- **C7 Evidence and delivery:** Independent repository tests cover positive lifecycle, migration, copy isolation, invalid data, storage failures and stale mutations; existing model tests, production build and the final existing loop suite pass. The actual local browser exercises the new lifecycle plus persistence/error handling. No new push or deployment occurs; delivery is a verified local working tree.
