# Local backend design

Keep the current model as the approval/invalidation authority. Add immutable reference seed definitions in `src/data/seed.ts` and a storage-injected synchronous repository in `src/data/database.ts`. The repository exposes snapshots and explicit mutations rather than leaking mutable stored objects. Persist schema version, reference tables, selected cycle and cycle records in one bounded JSON database document. Each cycle carries stable ID, title, created/updated timestamps, revision and validated model state. Injecting a Storage-compatible adapter permits deterministic failure/conflict tests without a browser.

Validate untrusted stored values before trusting them, including complete reference shapes, cycle identifiers and uniqueness, selection integrity, string/collection limits and state approvals. Initialization distinguishes no database, valid database and unreadable/corrupt storage. Legacy migration applies only when the database key is absent and uses the existing model decoder/validation boundary. Preserve legacy bytes until successful persistence. Corrupt database recovery must be explicit; do not silently replace it during ordinary reads.

Each mutation reads/validates the latest persisted document, compares expected revision, constructs and validates a copy, then calls setItem. Only a successful write publishes a saved result; exceptions preserve the prior durable document. Check both database-level lifecycle/selection conflicts and cycle-level state conflicts as appropriate. LocalStorage gives a synchronous atomic individual write, not a cross-tab compare-and-swap: document the remaining simultaneous read/write race honestly. Notify the UI of storage events and require an explicit choice before replacing unsaved local work.

`src/useWorkspace.ts` mediates repository snapshots, active model draft, pending/failed persistence and external-change notices. Maintain unsaved input when persistence fails and provide retry or explicit reload/recovery. `src/components/CycleManager.tsx` supplies named cycle controls and confirmation dialogs. `src/App.tsx` renders repository-provided evidence/reference data, delegates lifecycle actions and retains model-defined approval/export decisions. Cycle switches/reset/delete must settle or explicitly handle pending work; duplicate-as-draft clears downstream decisions and follow-up rather than inheriting authority from the source.

Use existing React/CSS and no new runtime dependency. Keep storage concerns outside the product language except meaningful save/error/conflict information. Test repository behavior independently and exercise the rendered lifecycle. README/local-backend documentation must distinguish this local mock from a deployed service.

Agreed API contract: `createLocalBackend(storageGetter, options)` is synchronous. Database schema version 1 includes a global revision, activeCycleId, immutable seed references and cycle records. Every mutation requires the expected database revision. Save, rename and reset also advance the affected cycle revision. Use at least one and at most twelve cycles; deleting the active cycle selects the first remaining cycle. A 20,000,000-character raw document bound supports twelve legal maximum escaping-heavy model states. Extract a reusable model `parseStoredState` boundary without changing existing tests. Explicit confirmed `resetDatabase` is the recovery route for corrupt/future databases; ordinary load never overwrites them. The legacy key remains a backup.
