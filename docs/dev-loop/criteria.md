# Throughline acceptance criteria

- **C1 Presentation:** A responsive React application preserves the supplied Throughline identity and four steps. All student data is labeled fictional and AI coaching is labeled simulated.
- **C2 Evidence and reasoning:** Users inspect and select evidence with dates and scope, write their own interpretation, review a scripted challenge, and confirm their own specific focus before planning. An older single-classroom observation cannot appear as current causal proof.
- **C3 Plan ownership:** The meeting has an editable 50-minute agenda, concrete teaching action and owner, distinct implementation and learning checks, and explicit educator consent before approval.
- **C4 Invalidation:** Evidence or interpretation changes revoke focus and plan approval, challenge review, consent and saved follow-up status. Focus edits revoke focus and plan approval, consent and saved follow-up status. Plan edits or revoked consent revoke plan approval and saved follow-up status. Draft text is preserved. Invalidated follow-up cannot be exported or shown as current approved work.
- **C5 Persistence and recovery:** Versioned local persistence preserves inputs, stage and valid approvals across reload. Invalid/corrupt or unavailable storage fails safely with a visible recovery path. Reset clears the stored demo. Imported browser storage is validated and cannot manufacture approval by inconsistent flags.
- **C6 Follow-up and export:** Approved plans support separate teaching-implementation status, fictional next-cycle evidence and an educator reflection. Saving requires meaningful input. Export contains the actual current selected evidence, reasoning, agenda, action, owner, checks and applicable follow-up. Export requires current approval.
- **C7 Accessibility:** Desktop and narrow mobile layouts have no horizontal overflow; controls have accessible names, keyboard operation and visible focus. Validation errors are announced and lead to the field requiring correction. Navigation communicates current and unavailable steps.
- **C8 Build and verification:** App tests, manual-loop tests and production build pass. The full flow, refresh recovery, invalidation, export and mobile layout are exercised against the actual local app. Deployment remains an explicit user-owned next step.
