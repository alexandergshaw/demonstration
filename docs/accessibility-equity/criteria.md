# Acceptance criteria

- C1: Browser-only reading preferences offer 100/125/150% text and default/spacious spacing, persist independently of cycles, reset to defaults, and expose safe corrupt/denied/quota/future-version behavior without silently overwriting unsupported data. Changes never alter instructional approvals or cycle text.
- C2: Relative text, wrapping and spacing preserve usable controls/content at 320/390 and desktop widths with enlargement; honor reduced motion/forced colors in CSS. Existing keyboard/focus/lock behavior remains usable. No unexecuted screen-reader, OS or zoom claim.
- C3: Long Guide/reader/kit dialogs enter at the heading/top; short name/destructive forms retain input/Cancel focus, Escape and return. Evidence actions have distinct source names. Mobile labels/save status remain available. Required owner/agenda hints and 4000-character limits are explicit and associated.
- C4: Optional equity questions preserve the rigorous goal, strengths, voice, response/language routes and uncertainty without inventing subgroup data. Optional accessParticipation text survives reload/switch/duplicate and reaches follow-up, approved text/HTML/handout; exports escape it. No equity score or mandatory response.
- C5: Legacy absent/empty accessParticipation preserves existing approval signatures. Present values have strict type/length validation; editing or clearing invalidates plan/reflection. Existing storage, stale-write, approval/export and maximum legal draft/database bounds stay correct. Immutable seed/tools/dependencies remain unchanged.
- C6: Independent actual source and targeted browser checks plus final app-tests/build pass on frozen bytes. Evidence identifies actual versus attributed tests and limits; no accessibility certification. Phase two and production release are separate later actions.
