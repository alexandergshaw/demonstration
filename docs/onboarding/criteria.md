# Acceptance criteria

- C1: Stable Guide/help entry supports optional four-part walkthrough, direct/Previous/Next navigation, close/replay/resume, contextual current-step entry and dismissible invitation. No forced modal, completion gate, auto-advance or implicit cycle navigation/approval side effect. An explicit Open this planning stage action must obey existing stage gates.
- C2: Three fictional practice topics cover aggregate overlap, dated/scoped observation and distinct implementation/learning checks. Each choice has specific explanatory feedback and retry; changed answers never retain stale feedback. Labels describe reviewed/practiced engagement, not competence. No content is inserted into active decisions.
- C3: Plain glossary and About preserve actual prototype assumptions, scripted/local privacy boundaries and confirmed presenter reset. All stage locks and prior disclosures remain valid; any separate learning-history reset affects only learning metadata, never PLC data or reading preferences.
- C4: Separate versioned progress stores only bounded navigation/review/attempt metadata. Missing, malformed, unsupported, denied/quota storage preserves existing bytes and workspace usability, with truthful session-only feedback. Session progress survives close/cycle switch and durable valid progress resumes after reload.
- C5: Existing title-first modal/focus return and section-change focus work with keyboard, 320/390 widths and 150% spacious reading settings. No inaccessible controls or clipping. Reduced-motion support and accessible feedback remain. AT/OS/native-print claims require actual instruments.
- C6: Existing protected functional/source hashes and new meaningful learning tests pass, plus app-tests/build on final frozen source. Actual independent source/browser checks bind accepted bytes. Parent commits/pushes and verifies production after local acceptance.
