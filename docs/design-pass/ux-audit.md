## Baseline findings

The baseline has robust business-state tests but visibly weak hierarchy and several concrete accessibility/interaction gaps. These findings apply to the pre-redesign files, not to a future candidate.

1. **P2 — Essential secondary text is too pale.** `src/styles.css` uses caption color `#758795` (3.71:1 against white; 3.45:1 against the page background `#f4f7f8`), empty-decision copy `#8b99a1` (2.93:1 against white), and intro copy `#637b8c` (4.43:1 against white; 4.11:1 against the page). These are normal-sized text, so the design's 4.5:1 requirement is not met. The ratios were calculated from the actual CSS colors using sRGB relative luminance. The focus outline `#61a7b0` is only 2.74:1 against white and 2.55:1 against the page. Correct the tokens and verify their actual surface pairings. Essential input boundaries also need a visible affordance; decorative dividers need not be treated as interactive boundaries.
2. **P2 — Validation is disconnected from the invalid control.** `Planner.submit` identifies an `errorField`, but `TextArea`, agenda inputs, consent, and implementation controls never receive `aria-invalid` or a description referring to the actual error. A single bottom alert and a separate “Go to the field” action are insufficient contextual feedback. Keep the model's validation authority, associate the message with the target, and retain keyboard recovery.
3. **P2 — Long decisions can overwhelm the sticky context panel.** `DecisionThread` renders complete authored fields directly. Legal 4,000-character interpretation/focus/action/reflection text, plus both follow-up checks, can create a very tall sidebar and long page. Use bounded previews and an explicit expansion that exposes the entire exact saved value. Do not silently truncate the durable record or export.
4. **P2 — Locked stages do not explain their prerequisite.** Meeting/follow-up buttons are disabled without an adjacent reason. Explain which educator approval is needed and keep the lock state discoverable to keyboard users, while refusing locked transitions.
5. **P2 — Cycle administration competes with the teaching task.** Reset is prominent in the top bar, while rename, duplicate, and delete share the large cycle toolbar. Group rare/destructive operations behind an explicit secondary disclosure. Keep cycle selection and creation discoverable and keep destructive confirmations.
6. **P2 — Failed-save drafts have no native leave protection.** The hook retains unsaved input and displays a banner, but neither the baseline App nor hook installs `beforeunload` while dirty. Browser refresh/close can discard that input outside the app's explicit Reload confirmation. An App-only dirty-state handler can address this without changing persistence semantics.
7. **Bounded recovery edge.** A cycle command conflict is stored as `operationError` without setting `externalChanged`. If a storage event is missed, the text advises reload but no reload action is shown until another edit changes the state. An explicit UI reload recovery action alongside operation errors is appropriate; this does not require a database rewrite.
8. **Verification risk, not a confirmed failure.** Name/confirmation dialogs unmount on Cancel without an explicit close/return-focus contract. Browser-test Cancel and Escape after menus are redesigned. This audit has not yet demonstrated that focus is lost in the baseline browser, so it is not presented as an observed browser defect.

Preserve factual source dates/scope and the fictional/scripted disclosures. A new comparison metric must use correct percentage-point semantics and must not infer individual student overlap or causality from aggregate counts. A cleaner interface must not imply a hosted database, live collaboration, or live AI.
